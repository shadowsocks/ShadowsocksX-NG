# 规则值与独立存储模型

**状态**：已接受（2026-10-19）。

## 背景

自定义规则逐条保存来源类别、上游版本和标签，但浏览直接根据文档归属赋予 `.custom`，运行规则不使用这些元数据。编辑仅透传来源，读取仅校验类别，额外字段没有保留必要事实。

`CustomRule`、`ProxyRule` 和 `RuleIdentity` 重复表达动作与匹配条件。原始 `RuleMatch` 枚举允许绕过校验，只有转换为规则身份时再次尝试规范化；同一条规则可能同时存在原始匹配条件与规范化匹配条件。领域类型直接实现 `Codable`，又使其表示与自定义文件、内置快照的格式绑定。

## 决定

- `ProxyRule` 是唯一的规范化动作与匹配条件值，其相等性用于规则身份、去重、停用与分析。不保留独立 `RuleIdentity` 类型。自定义条目的 UUID 仍是独立的持久编辑身份，符合 ADR-0023。
- `RuleMatch` 封闭构造入口。动态输入必须经校验和规范化；调用者只能读取匹配模式，不能用原始字符串直接组装领域值。移除规则身份中的再次规范化及失败后保留原值的路径。IPv4 与 mapped IPv6 仍保留不同身份，覆盖判定保持既有语义。
- 固定本地后缀 `local`、`localhost` 通过受控常量表示，存储转换支持其往返。普通自定义输入和自定义文档仍拒绝这两个后缀；不开放任意单标签后缀，保留显式允许 `cn` 的入口。
- 自定义文档与内置快照均使用独立存储 DTO。领域规则值、条目与集合不承担 JSON 编解码职责，也不携带 schema 版本。文件 adapter 管理版本、历史格式与领域转换，使领域模型和磁盘格式可以独立演化。来源归属仍由浏览集合表达，内置快照仍保留上游、许可、归属和转换报告等事实。
- 自定义条目不再保存 `source`。自定义文件写入 schema 3，读取兼容 schema 1/2，忽略旧来源字段；schema 1 没有停用集合。加载不重写文件，下次正常原子保存才写新格式。保留 UUID、条目顺序与孤立停用身份。旧客户端拒绝 schema 3，不支持降级读取。
- 存储 DTO 保持自定义条目的平铺 `id/action/match`、停用集合的 `action/match` 以及内置快照 schema 2 / converter 2.0.0 的磁盘形状。条目重复 UUID、重复规则身份、重复停用身份与无效匹配条件仍拒绝，不改写损坏文件。
- 内容 token 显式保持历史字符串格式，不依赖 Swift 类型调试描述。内容摘要、确定性排序和 ACL 字节不随内部表示变化而改变。保存意图、延迟投影及运行失败处理继续遵循 ADR-0026 与 ADR-0037。

## 取舍

存储 DTO 带来显式转换代码，但隔离了真实存在的两个文件契约，避免以后领域变化被迫迁移磁盘格式。没有为此引入通用存储协议或额外 adapter 抽象。

此决定取代 ADR-0024 中“自定义文档保留来源元数据与原 schema”的条款；内置快照的精简格式与其他决定继续有效。
