# 分离独立偏好，将 JSON 限定为代理监听配置

**状态**：已接受并实施（2026-10-19）。

当前 `settings.json` 同时保存监听配置和独立偏好，模式与开关等修改需要重写整份快照。将独立偏好直接分离，以缩小文件存储 module 的职责；不另建通用设置仓库，也不为原整快照保存路径专门建设集中管理 module。

- JSON 仅保存代理监听配置：本地端口、局域网启用状态、监听模式、端口、UDP 中继、身份验证用户名及密码引用；密码继续独立保存在 Keychain。保留四端口联合校验、凭据提交、原子保存与写入失败处理。
- 代理模式、规则默认动作、代理服务开关、系统代理开关与附加系统代理例外改用 UserDefaults。修改后执行现有运行或系统代理动作；不再为这些值提供 JSON 写入失败的报错与回滚路径。部署失败仍保留最新意图，遵循 ADR-0037；开关级联与系统代理行为不因更换存储而改变。
- 领域类型、文件 adapter 和文件路径均使用代理监听配置的专用命名，不保留通用 `settings` 名称来承载此文件职责。新增设置只有属于代理监听配置、需要其关联约束时才能加入；其他场景的偏好由所属 module 管理。
- 运行状态收敛仍可捕获一致的内存快照，用于配置派生和过期结果检查；该快照不定义统一持久化范围。现有轻量偏好、服务器库、自定义规则、活动目标及插件映射的存储不收拢到监听配置中。
- 不迁移旧 `settings.json`：新监听配置文件与新增 UserDefaults 偏好在没有保存值时使用各自默认值，现有开发配置需要重新设置。旧文件不读取、不删除，遗留 Keychain 条目不访问、不清理；用户重新保存的监听凭据继续按正常流程管理。此前已独立保存的 UserDefaults 偏好保持不变，不做整体重置。

分离后仅收拢实际仍存在的重复实现，不以统一持久化方式或恢复职责为目标增加抽象。极端文件损坏接受人工恢复，沿用 ADR-0040。本决定修订 ADR-0040 对保存失败保证的适用范围。
